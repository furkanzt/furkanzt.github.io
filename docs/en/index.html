View on GitHubfurkanzt/claude-tdd-bdd-harness

How it works4 steps

Every behaviour a program promises becomes a plain-English scenario tied to a real test, and the build fails when a promise has no working proof.

  1. 1

    Write the behaviour down

    Each behaviour is written as a short Given / When / Then scenario in plain English, one file per area of the product.

  2. 2

    Point it at its proof

    Every scenario names the test that proves it in a “Backed by” line, for example tests/test_pricing.py::test_discount_never_exceeds_cap.

  3. 3

    Check every link on each push

    A guard runs on every push and fails the build when a scenario has no proof, cites a test that no longer exists, or the coverage index is out of date.

  4. 4

    Mark what is not proven yet

    A behaviour without a test is allowed only when it is openly tagged @gap @wip. A bare @gap fails the build, and once the gaps reach zero they stay at zero.

Go deeper
  • Citations resolve three forms: Python tests (tests/x.py::test_fn), JavaScript tests (web/src/x.test.ts > does the thing) and checks that only a live system can run (scripts/quality/checks.py::check_fn).
  • The guard's own checkers are pure functions with red-path proofs on deliberately broken inputs, so the guard is itself tested.
  • A new test earns its citation only after it fails against a deliberate mutation of the code it protects.
  • An adversarial audit playbook lists the ways a green test can still lie, such as self-referential pins and vacuous fixtures, and runs on its own when you say "audit my tests".
  • Behaviour that only a running system can show is a first-class scenario tagged @loop: it runs on a schedule and its citation is still checked on every push.
  • In the plugin install, three hooks remind Claude at session start, on test edits and on commit. They never block; the guard on each push is the real gate.
  • Adoption is opt-in: it asks once per project and remembers a no.
  • What it does not claim: the guard checks that each scenario points to a real test, not that every line of code has a scenario. It makes unproven promises visible.
